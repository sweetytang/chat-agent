# 业务重构执行计划

## 1. 建立迁移后基线

- [ ] 确认工作区迁移子任务已验收并提交。
- [ ] 从 Git 根运行前端、后端、DTO、迁移和构建全量门禁。
- [ ] 记录三个超过 500 行文件的职责、调用者和现有测试。

## 2. 机械清理

- [ ] 后端运行 Ruff format/check 与 Mypy，审查自动修复后再保留。
- [ ] 前端运行 Prettier、ESLint、Stylelint 与 TypeScript，清理未使用导入、变量和显然不可达代码。
- [ ] 删除工作区内缓存、编译产物和错误跟踪的生成目录，完善忽略规则。
- [ ] 运行两侧全量测试，确保本批没有行为变化。

## 3. 死代码审计与删除

- [ ] 用 `rg` 和入口清单审计未引用模块、导出、组件、hook、服务、脚本和配置。
- [ ] 检查 FastAPI router、依赖注入、LangGraph/MCP 动态注册、Vite 入口和生成脚本，排除动态消费者。
- [ ] 对确认无用项建立删除清单，直接删除实现及失效测试/引用。
- [ ] 每组删除后运行最近测试和工作区全量门禁。

## 4. 后端结构重构

- [ ] 为 `api/runs.py` 的现有行为补足必要锁定测试。
- [ ] 按 schema、应用编排、事件输出和路由边界拆分，保持 endpoint、状态码、事务和 SSE sequence。
- [ ] 搜索并更新所有导入；运行 runs、graph、interrupt、thread、MCP 相关测试。
- [ ] 复查其他重复或复杂分支，只在证据充分时简化。

## 5. 前端结构重构

- [ ] 锁定 MCP 设置页现有 Server CRUD、导入、刷新、开关和错误状态合同。
- [ ] 拆分 `McpSettings/index.tsx` 的独立交互组件并保持 CSS Module 共置。
- [ ] 拆分 `useMcpSettings.ts` 的纯解析/转换与副作用职责，复用现有 service/domain 边界。
- [ ] 保留主题 4 文件基线和视觉合同；运行 UI 合同、类型、lint、测试和 build。

## 6. 分级缺陷处理

- [ ] 对执行中发现的问题按批准策略分类。
- [ ] 仅为阻断/直接相关缺陷先增加失败测试，再提交最小修复。
- [ ] 将无关非阻断问题记录为后续候选，不实现。

## 7. 最终验证

```bash
make check
make test
make build
make db-migrate
make check-api-types
```

- [ ] GitHub Actions 前端和后端工作流通过。
- [ ] 浏览器验证登录、线程、发送/停止、审批恢复、主题和 MCP 设置页面。
- [ ] 审查最终 diff，确认格式化、结构和行为修复批次边界清晰。
- [ ] 运行 Trellis check，更新必要规范后提交并完成子任务。
